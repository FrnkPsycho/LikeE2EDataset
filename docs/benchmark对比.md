# 相关 benchmark 对比

定位 LikeE2EDataset 与两个最相关的 benchmark 的差异：
- **CyberGym-E2E**（UC Berkeley，我们改进的对象）
- **AgentCyberRange**（复旦 SecSys，2026 年新出现）

---

## 0. 一句话定位

LikeE2EDataset = CVE 驱动的「端到端漏洞**处理**」基准：发现 → PoC → 补丁（白盒）+ 攻击 → 检测 → 处置（黑盒），攻防修三合一，真编译 + 重放攻击链判分，做题方交完整 agent（harness + 模型）。

## 1. 三方对比

| 维度 | CyberGym-E2E | AgentCyberRange | LikeE2EDataset（我们） |
|------|------|------|------|
| **定位** | 端到端漏洞「发现 + 修复」 | 攻击能力基准（offensive） | 端到端漏洞「处理」（攻 + 防 + 修） |
| **测什么** | 只给源码 → 找漏洞 → `poc.bin` + `fix.patch` | 黑盒多步渗透：Web 利用 + 后渗透（横向 / 提权 / 持久化） | 发现→PoC→**补丁**（白盒）+ 攻击→检测→**处置**（黑盒） |
| **环境** | 单 fuzzer 目标（解析器/解码器为主） | 多主机企业内网（156 内部主机、DMZ、分段网、蜜罐/诱饵） | 单题单应用 Docker（gateway / waf / frontend / target / blue 5 服务） |
| **漏洞类型** | 崩溃型为主（内存安全，C++/C） | Web 层（SQLi / SSRF / XSS / RCE / 逻辑） | 崩溃型（ASAN）+ flag 型 |
| **规模** | 920 任务 / 139 项目 | 110 漏洞 × 15 应用 + 8 个 range | 起步 1 样例，目标 5~10 题算通过率 |
| **评测对象** | agent（harness 内置，只换模型） | frontier 模型（CAGE 给 adapter：Codex/Claude Code/Qwen/Kimi） | 做题方交**完整 harness + 模型** |
| **判分** | 4 阶段（poc 崩 / 补丁后不崩 / 测试过 / GT 不崩） | 成功率（多步链是否打通） | 通过率（S1-S7 判据，真编译 + 重放） |
| **攻 / 防 / 修** | 攻（发现 + PoC）+ 修（patch） | 只攻 | **攻 + 修 + 防 三合一** |

## 2. 相对 CyberGym-E2E 的三个改进（立项方向）

1. **增加规模**——e2e 已有 920 题，我们从 1 样例起步、目标扩到 5~10 题做一期选型。
2. **更新漏洞**——e2e 数据不含 CVE 编号（只有 task_id + vul_commit + patch_commit），我们 CVE 驱动、对齐真实 CVE（样例 CVE-2025-24928）。
3. **适用中国大陆**——e2e 的 gcr.io / github / HuggingFace / Docker 四项在大陆要镜像替代；我们面向大陆环境落地。

## 3. 相对 AgentCyberRange 的差异

- **两条不同的轴**：他是「攻击的**深度 / 真实内网**」轴，我们是「漏洞**全生命周期（修得住 + 防得住）**」轴。
- **我们有、他没有**：修复（S2 补丁）+ 防御（S5 检测 / S6 处置 / S7 业务回归）+ S4 真值泛化。他的论文从头到尾是攻击，没有 patch / defense。
- **他有、我们没有**：多主机内网渗透的真实性（横向移动、提权、持久化、隧道）——我们停在单应用单漏洞。
- **共同点**：CVE 驱动、真环境、重放验证、测 agent 而非裸模型。
- **对我们的意义**：不是撞题，是互补。他验证了「真实 cyber range + agent 评测」这个大方向；我们「防御 + 修复」的角度是他明确没覆盖的空档，正是我们「端到端闭环」的独特点。他那个「多主机内网渗透」若将来想扩，是可借鉴的方向（但属另一个量级的工程成本）。
